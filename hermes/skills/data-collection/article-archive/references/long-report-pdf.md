# 研究型长报告 → PDF（build_article_pdf.py）

用途：把案例研究、机制分析、方法论梳理类长文写成 markdown，再用 `build_article_pdf.py` 转 PDF 交付（QQ 文档默认 PDF）。文章归档流程见 SKILL.md，本文件只管“写报告”这一类任务。

## 1. 写作前先核验

- 关键金额、年份、处罚/判决结果先用 `web_search` 核对，优先证监会处罚决定书、法院判决、权威财经媒体；官方文书与媒体口径不一致时并列标注（例：虚增利润 115 亿 vs 媒体 119 亿），不要单选一个当定论。
- 每个案例固定字段：时间、主体、手法拆解、关键数字、暴露路径、处罚或判决。缺哪一项就补查，勿用“约”“大量”糊过去。

## 2. 结构模板（用户要的分析深度）

版本说明 → 主题章节（每节：手法 + 1 至 3 个案例细节）→ 机制章 → 共性归纳 → 识别清单 → 附录（案例索引、对照速查）。

案例研究不能停在罗列事实：用户会追着要“利用了哪些监管或制度漏洞、手法的应用条件、最终怎么被发现”——首稿就按“漏洞—条件—暴露”三要素写，省一轮返工。机制章逐条对齐主题章节的编号，附录再给一张“漏洞—条件—暴露”对照行，便于速查。

## 3. markdown 方言限制（解析器按行切块）

- 首行 `# 标题` 是标题；`> ` 开头为元信息（作者/来源/数据区间/说明）。
- 章节标题必须是**独立成行**的 `**标题**`；正文里不要内联 `**`，否则星号被转义后原样显示。
- 不支持表格与列表渲染：条目用“· ”开头的独立段落，表格改写成逐条文字或附录对照行。
- 禁止 emoji 与生僻字：脚本做全字符覆盖检查，缺字直接 `PDF_FONT_FAIL`。
- 每个段落写在一行内，空行分段；段落内换行会被当作两块。

## 4. 构建与校验

```bash
PYTHONPATH= ~/hermes_data/rl-venv/bin/python ~/hermes_data/articles/build_article_pdf.py "<md路径>"
```

- 输出同目录同名 `.pdf`；成功标志 `PDF_OK:` 与 `[font] OK`，失败会明确报 SRC_NOT_FOUND / REPORTLAB_MISSING / PDF_FONT_FAIL / PDF_FAIL。
- 校验链：`pdfinfo` 看页数与标题 → `pdftotext` 抽全文核关键词（章节数与案例数要对得上）→ `pdftoppm -f N -l N -r 80 -png` 渲染后 `vision_analyze` 抽查版式（页数过 9 时文件名补零，如 `-06.png`）。
- 报告存放 `~/hermes_data/reports/`；交付用独立 `MEDIA:` 行，文字说明可与非音频文件同条发送（音频才必须独占回复）。

## 5. 终端纪律

- 构建与校验命令保持单条。`cd ... && python ... | tail` 这类组合命令会触发安全扫描审批，QQ 侧弹不出批准框而超时被 BLOCK；拆成独立调用（先构建，再 pdfinfo，再 pdftotext）。

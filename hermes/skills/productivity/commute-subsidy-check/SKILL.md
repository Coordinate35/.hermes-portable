# 通勤耗时测算与字节房补范围判定

## When to Use（触发条件）
- “这个房子/小区符合房补吗”“帮我算下到公司通勤”“步行/骑行/公交多久能到”“这个小区算不算在范围内”
- 需要给某个候选居住小区做“是否符合字节跳动房补”的判断

## 房补判定阈值（满足任一即达标，含等号）
1. 纯步行 **≤ 30 分钟**；或
2. 纯骑行 **≤ 20 分钟**；或
3. 混合（步行/骑行 + 公共交通）**≤ 20 分钟**

三条都不满足 → 不符合。结论里要写清楚是哪一条触发的。

## 口径与硬性规则
1. **居住端只到小区门**，不需要精确到楼栋。**每个门都要单独算一次**，每种方式取所有门里最快的那个。
2. **公司端精确到楼栋 POI**（如「大钟寺广场-2号楼」），不能用大地名（「大钟寺」）。
3. **方向：以小区门为起点、公司为终点**。单行/禁行会让往返不对称，以“早上进城”方向为准。
4. **只用百度地图**。不用 OSM、不用高德、不自行估算。
5. **三种方式各自端到端计算**：
   - 纯步行：门 → 公司
   - 纯骑行：门 → 公司
   - 混合：`min(门→上车站 步行/骑行)` + 公共交通 + `min(下车站→公司 步行/骑行)`
6. **公共交通不限地铁**：公交、地铁、混合线路都算，**取耗时最快的方案**（百度「公交」标签里已包含公交+地铁，列出多条候选）。
7. **不计**等车、进站安检、出站、找共享单车、还车时间。但**必须额外给一行“找车敏感性”**：若需要借共享单车，每端 +2～3 分钟。
8. 结论必须写明：是否达标 + 触发条件 + 三种方式各自最优时间与对应门 + 混合拆分明细 + 数据查询时间。

## 执行步骤

### 第 1 步：枚举小区所有门
```bash
PYTHONPATH= /usr/bin/python3 scripts/enumerate_gates.py "展春园小区" 131
```
- 百度 POI 可能缺门（实测有小区没有东门 POI），不要自行脑补；结论里写明「百度 POI 仅有 N 个门」。
- 门的地址字段可能是脏数据，以路线实际经过的街道为准。

### 第 2 步：定公司端 POI
- 用楼栋 POI，不要用园区/地名。
- 公司端只有一个点，不需要多变体（除非园区有多个门且差异明显）。

### 第 3 步：逐门跑三种方式（browser_exec）

百度地图网页版操作要点（实测可用）：
- 打开 `https://map.baidu.com/`，等 6 秒
- 点 `(369,45)` 打开出行方式面板，再点 `公交 / 驾车 / 步行 / 骑行` 标签（span/div 文本节点）
- 输入框：`.route-start-input`（门）、`.route-end-input`（公司楼栋）
- 联想列表：`.ui3-suggest-item`（按 `innerText.includes(名称)` 点击）
- 出现「请选择准确的起点/终点」时，点文本为 `选为起点` / `选为终点` 的第一项
- 结果文本：`document.body.innerText`，正则 `(\d+)\s*分钟[约]?\s*([\d.]+)\s*公里`（或 `米`）

公交/地铁方案的处理：
- 在「公交」标签下取**时间最短**的那条（列表里会同时给出票价、时间、总距离、步行距离）
- 点开该条看明细，拿到：上车站、下车站、**车程分钟数**、进出站步行距离
- 混合的接驳段仍要单独用「步行」「骑行」各查一次，不能用公交方案自带的步行距离代替

注意事项：
- 每次 browser_exec 调用开始时标签页可能被重置为 about:blank，**必须在同一次调用内重建会话**，单次调用建议跑 3–4 个查询。
- 赋值前先 `value=''` 并派发 `input` 事件。

### 第 4 步：汇总取最优 + 判定
每个门一张表：

| 门 | 纯步行 | 纯骑行 | 混合 |
|---|---|---|---|
| 门A | a1 | b1 | c1 |
| 门B | a2 | b2 | c2 |

取每列最小值，然后判定 `min(步行) ≤ 30` 或 `min(骑行) ≤ 20` 或 `min(混合) ≤ 20`。

### 第 5 步：输出
1. 结论：符合 / 不符合，触发了哪一条
2. 三种方式最优时间 + 对应门 + 距离
3. 混合拆分：门→上车站（步行/骑行 取优）+ 公共交通（方案名+车程）+ 下车站→公司（取优）
4. 逐门明细表（便于复核）
5. 找车敏感性：需借共享单车时每端 +2～3 分钟，对结论是否构成翻转
6. 口径：百度地图、查询时间、是否高峰

## 已知坑（实测踩过）
- **短接驳步行常赢**：步行近道骑行可能禁行（实测五道口站→西门：步行 480 m，骑行 1.3 km）。< 500 m 优先给步行。
- **骑行优势只在顺路段**：920 m 直线可达时骑行 6 分钟、步行 14 分钟。
- **最优门随方式变化**：同一小区，步行最优点、骑行最优点、混合最优点可能三个都不同；只算一个门会错两种。
- **POI 精度影响结果**：同一地铁站选「五道口站」vs「地铁五道口站-公交站」，骑行距离差 200 m。
- **地址字段不可信**：POI 地址可能与实际位置矛盾，以路径为准。
- **方向不对称**：单行/禁行会让“去程”和“回程”不同，统一按小区→公司算。
- **浏览器依赖**：需 Chrome 可启动且系统代理不通向失效代理；异常先看 skill `browser-exec-recovery`。

## 备注
- 阈值口径、方向、是否计找车时间均由用户 2026-11-11 明确；政策或口径变更时先改“房补判定阈值”与“口径”两节。
- **方向不对称实测**（展春园小区→大钟寺广场2号楼）：南门→公司骑行 20 min（3.2 km），反向却要 28 min（4.8 km）；西门→五道口站骑行 4 min，反向 7 min。所以方向绝不能省略。
- 基准案例：大钟寺广场2号楼 ↔ 展春园小区（4 个门），最新基准值见输出模板。

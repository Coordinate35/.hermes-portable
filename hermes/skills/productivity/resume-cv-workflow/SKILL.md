# 简历撰写/修改工作流

触发条件：用户提到改简历、写简历、润色简历、补充工作经历、求职材料，或提供他人 CV 作为参考模板。

## 关键背景

- 用户 = 魏俊杰（GitHub Coordinate35，coordinate35@qq.com，1995.03，华科本科）。
- 生涯：2018.07-2023.12 滴滴出行·微服务架构（接入层）资深研发 D7，角色演进：DevOps → 管控面负责人 → 转发引擎负责人 → 接入层技术负责人；2024.01-至今 抖音·服务架构·研发体验与效率 2-1。
- 工作史源数据：`~/Documents/summary`（GitHub Coordinate35/summary 本地克隆）：
  - `2023-12-14 五年半的工作/五年半的工作.md`：2018-2023 逐年工作内容+量化（管控平台覆盖率 6%→72%、单均有效上线时长 -50.2%、回滚率 -75.5%、事件循环<50ms、流量染色 2→50、上云扩容小时→分钟、BGP转静态、压缩/SSL复用/H2 降本等）。
  - 半年总结：`2025-06-29 2025H1总结/`、`2026-02-17 2025H2总结/`、`2026-08-09 2026H1总结/`（文件带日期前缀），工作内容在「做了的事情 → 工作」小节。2024 无半年总结，用简历原有项目 + 2025H1 提及补足。
- 参考结构模板：钟颖辉 CV v2（3 页 PDF）—— 头部一行式（姓名/性别年龄/电话邮箱/经验年限/意向/期望城市）→ 个人优势（量化 bullet）→ 工作经历（公司/职位/时间 + 「内容」+「业绩」）→ 教育 → 其他；项目经验并入工作经历，不单列。

## 流程

1. 读参考 CV（`pdftotext -layout xxx.pdf -`）提取结构模板；再读用户当前简历，确认已有内容与缺口。
2. **先 `cd ~/Documents/summary && git pull` 再读源文档**（用户明确要求：本地有仓库时必须先更新到最新，然后 `find . -maxdepth 1 -type d | sort` 确认有哪些半年总结）。
3. 从五年半/半年总结提取工作内容：把原始条目改写为简历语言（动词开头、量化结果、技术深度、影响力）；角色演进本身是亮点（晋升路径）。
4. 数字逐字取自源文档；文中的 x% 占位符保留并标注「（待补）」，汇总清单给用户，**绝不编造数字**（招聘材料真实性底线）。
5. 未知信息（求职意向、专业、团队规模、汇报对象）保持空白/标注待定，不猜测。
6. 输出：md 存 `~/hermes_data/` + docx（`uv run --with python-docx python3 scripts/md2docx.py in.md out.docx`），用 python-docx 读回段落验证后再交付（MEDIA: 路径）。

## Pitfalls

- 参考 CV 里的数字/项目是别人的（如钟的中信证券量化时延 -80%），**只借用结构，禁止复制其内容**。
- 引用 GitHub 仓库内容前必先 git pull——用户在本会话中断纠正过"如果本地有仓库，需要先更新到最新"。
- 系统无 pandoc / 无 python-docx 时用 `uv run --with python-docx` 临时环境，不要 pip install 污染系统。
- 交付时附 md 源文件路径便于用户续改；用户补完 x% 后可再出 PDF 版。

## 支持文件

- `scripts/md2docx.py` — md→docx 简易转换（标题/列表/行内加粗），用法：`uv run --with python-docx python3 md2docx.py <in.md> <out.docx>`

# 读书笔记工作流（Book Study Notes）

把一本书（epub/txt 入库后）精读并产出结构化读书笔记文档，含框架、脉络、结论。

## 触发条件

- "读一下这本书/阅读下这本书，帮我总结全书内容/整体框架/脉络/结论"
- "把 XXX 提炼成一份笔记/框架文档"
- 书已在听书书库（`~/hermes_data/ebooks/<书名>/`），用户要的是**文字化总结文档**而非朗读。

## 前置：确认书稿与章节地图

1. 书未入库 → 走 audiobook-reader 的下载/导入流程（add_book.py，导入后跑 verify_book.py 核查字数/章节完整性）。
2. 读完章节地图：`python3 -c` 读 `chapters.json` 打印 `章号 | 标题 | 段落数 | 字符数`（如 74 章 / 24.8 万字）。
3. 规划分组：正文 10 章左右 → 分成 **5 路并行**，每路 1-3 章；跳过版权/致谢/参考文献（参考文献仅小节标题可提）。

## 核心方法：并行子代理精读 + 超时兜底自读

### 1. 派 5 个并行子代理（delegate_task）

每个子代理的 context 必须包含：
- 章节文件路径格式：`/home/coordinate35/hermes_data/ebooks/<书名>/chapters/NNN.txt`（NNN 三位数字）
- 该路的**完整章节清单**（文件号 + 节标题 + 字符数），并指明重点文件
- 输出要求（JSON Schema）：
  - `sections[]`：每节 {file, title, summary, key_quotes[]}
  - `core_concepts[]` / `logic_chain` / `conclusions[]`
  - 每节 summary 200-400 字；key_quotes 用『』引号且注明出自哪个小节
- **硬性约束**：必须先真正 read_file 逐个读取，禁止凭书名猜测；不得编造书中没有的观点；文件读不到必须报告。

prompt 模板见 `references/subagent-read-prompt.md`（可直接改书名/章节号复用）。

### 2. 子代理结果的完整获取（重要）

- 汇总消息里每路的 summary 会被截断（`[SUMMARY TRUNCATED] ... offset/limit` 提示）。
- **必须**用 `read_file` 读取 `~/.hermes/cache/delegation/subagent-summary-<N>-<时间戳>.txt` 拿完整 JSON；单行超长时用 python 从 `{` 处 json.loads 后按需打印（如只看指定 file 的 section、或只看 conclusions）。
- 抽查子代理真实性：读过导读部分的话，比对关键引文是否与原文一致。

### 3. 超时兜底（实战：5 路里 1 路 600s 超时）

某路子代理超时/失败时**自己精读**该部分：
- 每批 9 个 `read_file` 并行（一次 turn 多个调用），两批读完 18 个文件；
- 自己读时按"每节小结"随手记录关键句，最后按同一 JSON 结构自产笔记。
- 不要重新派子代理补活（更慢且可能再超时）。

## 整合与文档产出

- 文档路径：`~/hermes_data/<书名>_读书笔记.md`（工作目录规范，不写 ~/ 根）。
- 文档结构模板（2026-09 实测用户反馈良好）：
  1. 书籍信息（书名/作者/译者/出版社/ISBN/原版/字数）+ 译名/版本说明
  2. 全书定位（一句核心问题引文）
  3. 框架总览（三幕/三部分结构表：铺垫-理论-应用-总结 + 一条主线）
  4. 逐章脉络（每章：主题 + 要点 + 原文关键句）
  5. 核心概念表（概念 | 定义/要点）
  6. 核心结论（理论层 + 现实判断层，条列式）
  7. 局限与阅读提示（数据截止时点、需读者延展的后续变局）
  8. 附录：术语速查
- 正文用 `write_file` 一次性写出（20KB 级 accepted）。
- 完成后可选：接 mindmap-rendering 出思维导图并附进文档（`![书名](书名_思维导图.png)` 相对路径）。

## 交付

- QQ Bot：文档路径 + 结构概览用文字回复（长文场景），一句话核心结论可语音播报。
- 归档：`fact_store` 记一条（书→笔记路径+核心结论一句话），便于后续会话直接引用。

## 不要做的事

- ❌ 不要自己从头到尾读 25 万字正文（上下文会爆）— 子代理分组读，超时部分才自读。
- ❌ 不要把子代理截断的 summary 当完整结果直接整合（中部丢失，导致章节摘要残缺）。
- ❌ 不要跳过"逐字核对"：读书笔记里的关键数字/判断必须能在原文找到出处。
- ❌ 不要改书库文件；只读 chapters/ 下 txt。
- ❌ 不要给用户只发"笔记已完成"不附路径与结构概览。

## 相关技能

- audiobook-reader：书稿导入/章节切分/完整性核查（本书稿来源）。
- mindmap-rendering：把框架图化（markmap 路线），并附进笔记文档。
